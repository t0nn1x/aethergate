# Mobile quit button no-op (quit execution lived in UI callback)

**Date:** 2026-02-12 01:00
**Files:** `src/entities/Ui/GUI/MainScreen/main_screen.gd`, `src/world/overworld/overworld.gd`
**Severity:** high

## Problem

On mobile, pressing Quit did not close the app reliably.

## Root Cause

Quit execution was coupled to the UI button callback (`MainScreen._on_quit_pressed`) and happened inline during input handling. The stage-level signal consumer (`Overworld._on_main_screen_quit_requested`) did not execute quit logic at all, so ownership was split and behavior was fragile on mobile runtimes.

## Solution

- Removed direct `get_tree().quit()` call from `MainScreen` button handler.
- Kept `MainScreen` as a pure signal emitter: `quit_requested.emit()`.
- Implemented platform-aware app exit in `Overworld`:
  - `quit_requested` now triggers `call_deferred("_quit_application")`.
  - `_quit_application()` sends `NOTIFICATION_WM_CLOSE_REQUEST` then calls `get_tree().quit()`.
  - Web runtime is explicitly logged and ignored.
- Added `[FIX][Quit]` logs for runtime visibility.

## Prevention

- Keep UI nodes declarative: emit intent signals, do not own process/app lifecycle operations.
- Execute shutdown at composition root/stage controller and defer it outside input callbacks.
- Add platform-specific close-path logs for mobile/web behavior verification.
