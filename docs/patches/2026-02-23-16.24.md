# Player layered sprites bypassed world Y-sort due to fixed z_index

**Date:** 2026-02-23 16:24
**Files:** src/entities/Player/player.tscn
**Severity:** medium

## Problem

Player body/head layers rendered above world objects while legs respected Y-sort.
Result: only legs appeared correctly sorted against world geometry.

## Root Cause

Layered sprite nodes (`Body`, `Head`, `WeaponBack`, `WeaponFront`) used explicit `z_index` values.
These fixed Z overrides broke consistent Y-sort behavior relative to world objects under `WorldYSort`.

## Solution

Removed explicit `z_index` from player layered sprite nodes so all layers share the same Y-sort behavior.
Internal visual stacking now relies on child order in `VisualRoot` instead of fixed Z offsets.

## Prevention

- For Y-sorted entities, avoid hard `z_index` on visual body-part layers unless intentionally opting out of world Y-sort.
- Prefer node draw order within the character root for intra-character layering.
- Add a visual smoke test where player walks behind/around occluders and verify all body parts sort together.
