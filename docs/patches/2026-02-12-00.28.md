# Main menu audio logic duplicated in UI scene (refactor to central service)

**Date:** 2026-02-12 00:28
**Files:** `src/entities/Ui/GUI/MainScreen/main_screen.gd`, `src/Utilities/music_player.gd`, `project.godot`
**Severity:** medium

## Problem

Menu audio worked, but `MainScreen` contained low-level audio concerns (stream loading, pooling, music selection, loop behavior). This made the UI script harder to maintain and encouraged duplication when adding audio to other scenes.

## Root Cause

Audio orchestration was implemented directly inside a single UI scene instead of a reusable project-level service.

## Solution

- Added `MusicPlayer` autoload service (`src/Utilities/music_player.gd`) with:
  - pooled SFX playback,
  - UI hover/click configuration helpers,
  - random folder music selection and loop handling,
  - stream caching,
  - MP3 byte-loading fallback via `AudioStreamMP3`.
- Registered service in `project.godot` `[autoload]`.
- Reduced `MainScreen` audio code to thin orchestration calls:
  - configure once on ready,
  - one-line hover/click playback calls,
  - one-line start/stop menu music calls.

## Prevention

- For shared audio behavior, use a centralized autoload/service and keep scene scripts focused on UI state and interactions.
- Avoid duplicating resource-loading and pooling logic in multiple scenes.
