# Creature spawn zone picker not visible + severe editor lag

**Date:** 2026-02-15 22:48
**Files:** `src/Gameplay/Creatures/Spawning/creature_spawn_zone.gd`
**Severity:** high

## Problem

The custom zone inspector picker did not reliably appear, and selecting/inspecting zone nodes caused major editor lag.

## Root Cause

Two editor-only issues in the `@tool` picker implementation:
1. The script called methods on script-backed `Resource` placeholders in editor context (`catalog.call("rebuild_indices")`, `catalog.call("get_all")`). Placeholder instances do not support these method calls, producing repeated inspector errors.
2. Picker build eagerly loaded preview textures for every creature (`sprite_sheet`/`source_sprite_path`), which loaded hundreds of textures in one pass and stalled the editor.

## Solution

- Reworked catalog read path to use exported property access only:
  - Read `catalog.get("creatures")`
  - Read per-creature fields with `get("...")`
  - Compute fallback IDs in-zone (no cross-resource method calls)
- Removed eager preview loading for all entries.
- Added lazy preview loading for only the currently selected picker item.
- Added shared static picker cache so multiple zone nodes reuse one built catalog list.
- Added `[FIX][CreatureSpawnZone2D]` logging when rebuilding picker cache.
- Marked read-only picker fields as read-only in inspector usage metadata.

## Prevention

- In Godot editor `@tool` code, avoid calling methods on script-backed resources loaded as placeholders; prefer exported-property reads for inspector tooling.
- Never preload full texture sets for inspector convenience features; load preview assets lazily and cache narrowly.
- Share editor-only caches across node instances to avoid repeated expensive refreshes.
