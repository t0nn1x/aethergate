# Desktop cursor hotspot drift caused inaccurate move/select targeting

**Date:** 2026-02-19 14:01
**Files:** `src/core/platform_display_settings.gd`, `src/Gameplay/Player/Input/player_mouse_input_adapter.gd`, `src/Gameplay/Player/Components/Input/player_input_component.gd`
**Severity:** medium

## Problem

Mouse targeting felt inaccurate on desktop: tap-to-move indicators appeared below the cursor nose, and creature click selection felt offset from the visible pointer tip (especially noticeable at small camera zoom).

## Root Cause

Two issues combined:

1. Desktop cursor hotspot changed while mouse buttons were pressed (`+1,+1` offset), so the logical pointer position shifted during click interactions.
2. Mouse click handling used viewport/global mouse reads instead of the raw input event position at click time, which increased perceived mismatch in world-space targeting.

## Solution

- Removed press-state hotspot shifting from desktop cursor handling and kept a stable hotspot at the cursor nose.
- Simplified desktop cursor application to set the custom cursor once (no per-click hotspot mutation).
- Added debug log `[FIX][Cursor]` when applying desktop cursor, including path/hotspot/texture size for quick validation.
- Switched mouse input routing to use `InputEventMouseButton.position` / `InputEventMouseMotion.position` directly.
- Unified hold-retarget mouse world resolution through `_queue_move_target(screen_position, ...)` so world conversion always uses the same screen coordinate source.

## Prevention

- Do not mutate cursor hotspot dynamically for visual pressed-state effects; this changes interaction coordinates.
- For click-precise interactions, prefer event-provided screen positions over frame-polled mouse coordinates.
- Validate cursor alignment with a simple smoke test at multiple zoom levels: click ground and creature edges, verify marker/selection aligns with cursor nose.
