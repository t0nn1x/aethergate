# Switch main menu background source from ocean sets to cloud sets

**Date:** 2026-02-11 16:51
**Files:** src/entities/Ui/GUI/MainScreen/ocean_background_controller.gd
**Severity:** low

## Problem

User replaced parallax source assets with cloud variations (`Clouds 1..8`) and requested the menu to use these sets instead of ocean variants.

## Root Cause

The loader logic was generic but still semantically bound to ocean naming and logs, making behavior unclear and potentially brittle if non-cloud folders appear in the same root.

## Solution

- Added explicit set filter with `background_set_prefix = "Clouds "`.
- Folder discovery now only picks directories matching the configured prefix.
- Updated runtime logs and warnings to clearly indicate cloud selection and cloud-layer assignment.
- Kept existing mixed-size filtering and framing safeguards intact.

## Prevention

- Keep background-set routing configurable via explicit prefix/tag instead of relying on implicit folder contents.
- Preserve diagnostic logs identifying selected folder family to speed visual debugging.
