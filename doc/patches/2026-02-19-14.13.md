# Move-pointer click point drift at low zoom (mouse world mapping mismatch)

**Date:** 2026-02-19 14:13
**Files:** `src/Gameplay/Player/Components/Input/player_input_component.gd`, `src/Gameplay/Player/Input/player_mouse_input_adapter.gd`
**Severity:** medium

## Problem

After stabilizing cursor hotspot, creature taps felt correct but ground click move-pointer still appeared below click position at lower zoom (for example zoom 2).

## Root Cause

Ground move targeting and pointer placement depended on screen-to-world conversion path that was not consistently aligned with camera-aware mouse world mapping under all zoom levels. Creature taps were less affected because selection used radius-based hit testing.

## Solution

- For desktop mouse move requests, used `Creature.get_global_mouse_position()` as authoritative world click point at press time.
- Kept touch path unchanged (`InputEventScreenTouch.position` -> screen-to-world) to preserve mobile behavior.
- Updated `_screen_to_world` to prefer active camera conversion (`Camera2D.get_screen_to_world`) before canvas-transform fallback.
- Added debug logging (`[FIX][Cursor] move_click ... delta=...`) to compare conversion paths and validate residual drift quickly.

## Prevention

- For precision desktop pointer interactions, use camera-aware mouse world mapping for click placement.
- Keep a single conversion strategy per input type; avoid mixing different coordinate sources for the same action.
- Validate pointer placement at min/max camera zoom values during manual QA.
