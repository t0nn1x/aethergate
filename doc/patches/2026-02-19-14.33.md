# Window-space vs viewport-space mouse coordinates caused stable click offset

**Date:** 2026-02-19 14:33
**Files:** `src/Gameplay/Player/Input/player_mouse_input_adapter.gd`, `src/Gameplay/Player/Components/Input/player_input_component.gd`
**Severity:** high

## Problem

Ground click targeting remained offset at low zoom despite earlier fixes. Logs showed stable non-zero delta between queued world point and mouse world point (`delta=(3.0, 21.5)`).

## Root Cause

Mouse clicks used raw `InputEventMouseButton.position` (window-space), while world conversion and `get_global_mouse_position()` rely on viewport/canvas-space. With viewport offset/scaling in runtime, mixing these spaces introduced a constant click offset.

## Solution

- Restored/use viewport mouse coordinates for desktop mouse input:
  - `viewport.get_mouse_position()` via `_get_mouse_viewport_position(...)`.
- Applied this to both button press and hold-motion paths.
- Kept debug logs but now include both raw and viewport screen positions for verification.

## Prevention

- Do not mix window-space and viewport-space coordinates in the same input conversion pipeline.
- Keep debug logs showing both raw and transformed coordinates when calibrating cursor/click precision.
- Validate click precision across zoom levels and window/fullscreen modes.
