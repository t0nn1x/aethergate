# Main menu background framing mismatch and mixed-size layer filtering

**Date:** 2026-02-11 16:43
**Files:** src/UI/GUI/MainScreen/ocean_background_controller.gd
**Severity:** medium

## Problem

Main menu background looked zoomed/cropped compared to the source ocean image. The visual framing was inconsistent across starts.

## Root Cause

Two issues combined:
1. Background layers were fitted with a crop-prone mode, which could trim edges depending on viewport fit.
2. Ocean folders can contain mixed-size PNGs (e.g. mostly 576x324 plus a larger 2304x1296 image). Previous filtering relied on image-file loading that could be unreliable at runtime and allowed mismatched layers to slip into composition, changing perceived scale/framing.

## Solution

- Switched background `TextureRect` fit to `STRETCH_KEEP_ASPECT_CENTERED` to avoid crop and preserve full framing.
- Reworked layer-size filtering to use loaded `Texture2D` dimensions (`load(path) as Texture2D`) and bucket files by size.
- Selected the most common size bucket as canonical and excluded mixed-size outliers.
- Added explicit `[FIX][OceanBackgroundController]` logging for selected folder and filtering results.

## Prevention

- For parallax asset packs, validate layer dimensions before assignment and reject mixed-size outliers unless explicitly supported.
- Prefer runtime texture metadata (`Texture2D.get_width/get_height`) over raw file parsers for consistency with imported resources.
- Keep background fit mode explicit (`keep aspect centered` vs `covered`) and tied to expected artistic framing.
