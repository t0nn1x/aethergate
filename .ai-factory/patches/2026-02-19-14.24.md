# Ground click drift fixed by unifying queued world coordinates to screen-event mapping

**Date:** 2026-02-19 14:24
**Files:** `src/Gameplay/Player/Input/player_mouse_input_adapter.gd`, `src/Gameplay/Player/Components/Input/player_input_component.gd`
**Severity:** medium

## Problem

Ground move-pointer placement was consistently below the visual cursor nose at low zoom. Debug logs showed stable delta between queued click world and `get_global_mouse_position()` paths:
`delta=(3.0, 21.5)`.

## Root Cause

Mouse move clicks and hold retarget were using a different world-coordinate source than the creature tap path. Mixing input coordinate paths produced a stable world-space offset that became visually larger in pixels at low zoom.

## Solution

- Switched mouse move queuing to screen-event world conversion (`_screen_to_world(mouse_event.position)`), same coordinate path as creature selection.
- Kept debug delta logging (`[FIX][Cursor] move_click ...`) to verify mapping under zoom.
- Unified hold-retarget path to `_queue_move_target(_last_pointer_screen_position, true)`.

## Prevention

- Use a single coordinate conversion path for all mouse click-driven interactions in the same input component.
- Keep temporary conversion delta logs when calibrating cursor accuracy across zoom levels.
- Validate click alignment at min/default/max zoom in manual QA.
