# Move pointer/arrival mismatch from non-authoritative marker target

**Date:** 2026-02-25 10:42
**Files:** src/Entities/Player/Services/player_move_request_service.gd, src/Entities/Player/Components/Input/player_input_component.gd, src/Entities/Player/Components/Input/player_move_pointer_component.gd
**Severity:** high

## Problem

Click-to-move feedback felt inaccurate:
- The move pointer appeared offset from the click location.
- The player often did not arrive at the visual center of the move pointer marker.

This made movement feel unreliable and "off".

## Root Cause

Two coordinate-authority mismatches existed in the move flow:

1. `PlayerMoveRequestService` emitted the *requested* target (`world_position`) to pointer listeners, while navigation actually moved to the *resolved/snapped* target (`resolved_world_position`).
2. `PlayerMovePointerComponent` still had a desktop-only hardcoded visual offset enabled by default (`Vector2(-3.0, -21.5)`), so marker rendering diverged from actual move target even when input conversion was correct.

Additionally, hold-retarget cache used the pre-resolution world point, not the accepted target.

## Solution

- Updated `PlayerMoveRequestService.request_move_target(...)` to emit `resolved_world_position` (authoritative navigation target) instead of requested raw position.
- Added `[FIX][MoveTarget]` debug logs for queued and rejected requests (blocked/navigation rejection reasons).
- Updated `PlayerInputComponent` hold-retarget cache to store accepted target (`accepted_target as Vector2`).
- Disabled desktop marker offset by default in `PlayerMovePointerComponent` (`apply_desktop_click_anchor_offset = false`, `desktop_click_anchor_offset_world = Vector2.ZERO`).
- Added `[FIX][MovePointer]` debug log showing marker target/visual position/offset.

## Prevention

- Keep one authoritative target through the whole pipeline: input request -> resolved target -> nav target -> pointer visualization.
- Avoid default visual offsets in pointer markers; if needed, keep them opt-in and explicitly calibrated.
- In code review, verify signal payloads represent applied state (resolved/accepted), not just requested input.
- Add movement QA cases that check both click alignment and final arrival alignment at several zoom levels.
