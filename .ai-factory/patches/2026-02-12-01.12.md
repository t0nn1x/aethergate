# Mobile quit still no-op after signal-only refactor (restore direct deferred quit)

**Date:** 2026-02-12 01:12
**Files:** `src/UI/GUI/MainScreen/main_screen.gd`, `src/World/Overworld/overworld.gd`
**Severity:** high

## Problem

After moving quit execution to `Overworld`, mobile quit still did not reliably close from main menu.

## Root Cause

Quit depended on stage-level signal consumption and did not guarantee execution in the UI owner path where the request originated.

## Solution

- Added direct deferred quit fallback back into `MainScreen`:
  - `quit_requested.emit()` remains for architecture compatibility.
  - `call_deferred("_quit_application")` now runs locally.
  - `_quit_application()` triggers WM close notification + `get_tree().quit()`.
- Removed web-specific handling from this quit path.
- Simplified `Overworld` quit handler to logging only.

## Prevention

- For critical lifecycle actions (quit), keep a direct local execution path in the initiating screen, even if signals are also emitted to orchestration layers.
- Use deferred execution for lifecycle calls triggered by UI input callbacks.
