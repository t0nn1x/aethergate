# Mobile export menu audio silent (ResourceLoader-first + manifest fallback)

**Date:** 2026-02-12 00:38
**Files:** `src/Utilities/music_player.gd`, `src/UI/GUI/MainScreen/main_screen.gd`
**Severity:** high

## Problem

Menu audio worked on desktop/editor but was silent on mobile export builds.

## Root Cause

Two export-sensitive assumptions were present:
1. MP3 loading preferred `FileAccess` byte reads (`AudioStreamMP3`) before imported resources. In exports, original source files may be stripped while imported streams remain loadable.
2. Random music playlist discovery relied on `DirAccess` directory listing under `res://`, which can return empty in packaged/mobile builds.

## Solution

- Updated audio loading to prefer `ResourceLoader`/`load()` for all audio paths, then fallback to raw MP3 bytes only if needed.
- Added export-safe fallback manifest support to `play_random_music_from_folder(...)`.
- Wired `MainScreen` with `menu_music_fallback_tracks` (defaulting to current menu tracks) and passed it to the music playback calls.
- Added `[FIX][MusicPlayer]` logs around folder listing failure and manifest fallback selection.

## Prevention

- In Godot exports, avoid assuming original asset files are readable via `FileAccess`; prefer imported resource loading first.
- Do not rely solely on runtime `DirAccess` listing for `res://` music discovery on mobile/export.
- For random media selection in exported builds, keep a deterministic fallback track manifest.
