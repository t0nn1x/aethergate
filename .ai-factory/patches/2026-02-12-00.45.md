# Menu audio mobile fix refactor: explicit playlist + import-only loading

**Date:** 2026-02-12 00:45
**Files:** `src/Utilities/music_player.gd`, `src/Entities/Ui/GUI/MainScreen/main_screen.gd`
**Severity:** high

## Problem

Mobile/export menu audio remained fragile and the prior fix made the API noisy (extra fallback parameters per call) and harder to maintain from UI scripts.

## Root Cause

1. Runtime folder discovery and raw file loading paths were still mixed into the service behavior, creating export edge cases and bloated call signatures.
2. UI scene code passed repeated music-selection arguments on each call, increasing coupling.

## Solution

- Refactored `MusicPlayerService` to a cleaner, configuration-first API:
  - `configure_menu_music(track_paths, volume_db, bus_name, loop)`
  - `play_menu_music(force_new_selection)`
- Switched to import-only loading via `ResourceLoader`/`load()` (no raw `FileAccess` MP3 byte path).
- Replaced folder enumeration with explicit exported playlist in `MainScreen` (`menu_music_tracks`).
- Removed music-finished callback flow and applied looping directly on stream types (`AudioStreamMP3`, `AudioStreamOggVorbis`, `AudioStreamWAV`).
- Kept pooled SFX architecture unchanged.

## Prevention

- For exported/mobile safety, prefer explicit resource lists over `DirAccess` discovery for critical runtime media.
- Keep autoload services configuration-driven, with thin one-line calls from UI scenes.
- Avoid callback-heavy orchestration when native stream loop flags satisfy the requirement.
